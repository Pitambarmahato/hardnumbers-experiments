# earnings-release-ai-signal: Jev vs a local 7B model on earnings releases

Tests whether an AI model's bullish / neutral / bearish call on an earnings press release matches the direction of the
stock's next-session move. Four arms on the same 476 SEC 8-K Item 2.02 releases (accepted 2026-07-15 to 2026-08-31):
Jev (`jev-1.13.0`, TypeSafe AI), a local Qwen2.5-7B (Ollama 0.35.0, digest `845dbda0ea48`), a keyword-rule baseline, and an
"always up" control. Run 2026-10-03 to 2026-10-05, Python 3.14.6, standard library only.

Article: not yet published on hardnumbers.dev. This README will link it when it is.

**Research, not financial advice.** Nothing here places orders or connects to a broker.

## Headline numbers

Hit rate = share of non-neutral calls whose direction matched the sign of the stock's return minus SPY's. Primary window:
last close at or before the filing's acceptance to the close of the first session that starts after it.

| Arm | Non-neutral calls | Hit rate | 95% Wilson interval | Binomial p | Next open to close (secondary) |
| --- | --- | --- | --- | --- | --- |
| Jev | 392 | 56.1% | 51.2% to 61.0% | 0.0175 | 49.5% |
| Local Qwen2.5-7B | 379 | 50.4% | 45.4% to 55.4% | 0.918 | 50.4% |
| Keyword rules | 398 | 48.7% | 43.9% to 53.6% | 0.652 | 48.7% |
| Always up | 476 | 46.8% | 42.4% to 51.3% | 0.184 | 50.4% |

- The pre-registered "beats chance" line was a Wilson lower bound above 50% **and** p below 0.0167 (0.05 / 3 arms). Jev missed
  it on p (0.0175). See [`PREREGISTRATION.md`](./PREREGISTRATION.md) for the four hypotheses and how each was scored.
- Jev median latency 366 ms (p95 446 ms; three calls took 9.4, 19.0 and 19.6 s). Local 7B median 8.8 s on one 24 GB Apple
  Silicon Mac. Jev cost about $0.085 per 1,000 releases at its published input price ($0.042 per million tokens), estimated
  from the tokens its API reported.
- Everything above is regenerated by `python3 analyze.py` from the committed files.

## Files

| Path | What it is |
| --- | --- |
| `collect.py` | `events`: samples Nasdaq/NYSE tickers and finds Item 2.02 8-Ks on SEC EDGAR. `text`: fetches each exhibit 99.1. Needs `SEC_USER_AGENT`. |
| `prices.py` | `fetch` daily bars (Yahoo's unofficial chart endpoint), `returns` writes abnormal returns, `selftest` checks the timing rules. |
| `arms.py` | The four arms. The Jev client refuses any request that could pass the spend cap. |
| `run_arms.py` | Resumable runner with stop rules and a selftest (14 checks, fake clients only). |
| `analyze.py` | Scores the hypotheses. Falls back to `published/` when `data/` is absent. Selftest uses synthetic data (12 checks). |
| `dashboard.py`, `make_cover.py` | A read-only HTML table of each arm's call per release, and the article cover. Both read `data/`. |
| `published/sample_with_returns.jsonl` | The 500 sampled events: accession, ticker, acceptance time, entry/exit dates, returns, and the length of each exhibit. |
| `results/results.jsonl` | One row per arm per release (plus the Jev repeat check in `results/determinism/`). Raw model responses included. |
| `results/analysis.json` | Every number in the article's tables. |
| `PREREGISTRATION.md` | Hypotheses, thresholds and the changes made before any outcome was scored. |

Not committed: raw filing text and raw prices (`data/`). SEC filings are public and Yahoo's data is not ours to
redistribute; `collect.py` and `prices.py` rebuild them.

## Requirements

- Python 3.14 (any recent Python 3 should work; standard library only).
- `SEC_USER_AGENT` set to a contact string (SEC fair access): `export SEC_USER_AGENT='Your Name you@example.com'`.
- For the local arm: Ollama with `qwen2.5:7b` pulled. For the Jev arm: a TypeSafe API key in `TYPESAFE_API_KEY` (or a
  `chmod 600` file named by `JEV_ENV_FILE`). The runner caps Jev spend at `JEV_SPEND_CAP_USD` (default 0.50).

## How the results were produced

```bash
$ export SEC_USER_AGENT='Your Name you@example.com'
$ python3 collect.py events --sample 1600
$ python3 prices.py fetch && python3 prices.py returns
$ python3 run_arms.py sample --n 500 && python3 collect.py text
$ python3 run_arms.py run --arms rules,always_up,qwen2.5-7b
$ python3 run_arms.py run --arms jev          # needs TYPESAFE_API_KEY
$ python3 analyze.py
```

**Not re-run end to end from a clean checkout.** What was verified: `analyze.py` rebuilt from only the committed
`results/results.jsonl` and `published/sample_with_returns.jsonl` (no `data/` directory) gives an `analysis.json` identical
to the original, and the selftests pass. SEC and Yahoo data can change, so a fresh collection may not match exactly.

## Deviations from this repo's reproduction standard

- **Needs a paid API key** for one of four arms, and network access for EDGAR and Yahoo.
- **Not deterministic for Jev:** the label was identical on 20 of 20 releases across 3 repeats, but its confidence moved by up
  to 0.07 between repeats. The local arm ran at temperature 0, and its repeat check was dropped because Ollama's prompt
  cache would answer repeats without recomputing.
- **Machine-specific latency:** the local numbers are from one 24 GB Apple Silicon Mac. Jev's latency includes a
  network round trip over a residential connection.
- **Prices come from an unofficial endpoint** and were not cross-checked against a second source.

## Known issues

- Three Jev calls stalled (9.4, 19.0 and 19.6 s against a 366 ms median). They are kept.
- Eight local calls first showed 0.4 to 0.8 s because Ollama served their prompts from cache after a timing test. Those
  rows were removed and re-run; the local maximum (15.5 s) includes a model load.
- Three releases had near-empty exhibits (12, 47 and 54 characters). Jev and the rules arm have rows for them; analysis
  excludes every release under 500 characters for all arms (476 of 500 remain; 21 more had no exhibit 99.1).
- The keyword baseline is heavily bullish (earnings releases are written to sound positive) and was not tuned.
- Jev's training cutoff is not published, and company names stayed in the text.
- One earnings season only. Multi-day drift, trading costs and after-hours liquidity were not tested.
